Shorter files padded with silence. Typed metadata (bEXT, iXML, etc.) taken from the **first** input file. Output path defaults to `Merged_YYYYMMDD_HHMMSS.wav` in the first input's directory.- **split**: Reads PMAL metadata chunk to determine track layout, extracts each track's channels into separate WAV files in the same directory as the merged file.## Architecture Essentials### PMAL Chunk (Custom Metadata)- `WavMetadataChunk` reads/writes a custom `pmal` chunk appended after the WAV `data` chunk- Stores `TrackMetadata[]` as JSON: per-track file name, channel count, data length, typed metadata, and raw preserved chunks- Split reads PMAL to know how to reconstruct original files### Typed WAV Chunk Parsers`WavChunkParsers` handles 6 chunk types with Parse/Serialize round-trips:- **bEXT** (bext) — Broadcast Extension (AES3 standard, 602 bytes minimum)- **iXML** (ixml) — Interchange XML metadata- **INFO** (list) — RIFF key-value tags (ISFT, IART, INAM, etc.)- **cue** (cue ) — Cue points- **smpl** (smpl) — Sample loop data- **adtl** (adtl) — Audio Data Link List (labels, notes)Chunk ordering in merged output:1. Pre-data: bEXT → iXML → INFO2. data3. Post-data: cue → smpl → adtl4. PMAL (after everything)### Merge Logic (`MergeCommand.cs`)- Reads all files with `WaveFileReader`, validates matching sample rate + bit depth- Calculates max samples per channel across all files- Builds entire file in-memory as `byte[]`, interleaves samples track-by-track- Writes typed metadata chunks from first file's metadata### Split Logic (`SplitCommand.cs`)- Reads PMAL chunk to get track layout- Uses `WaveFileWriter` to write each track's channels- Appends typed metadata chunks and raw preserved chunks after writing audio data### Key Constraints- **Odd-length chunks must be padded** with a null byte to even boundary — done everywhere (merge, split, parsers)- **Little-endian** byte order for all chunk sizes (`BitConverter.IsLittleEndian` guard in `WriteInt32LE`)- **NAudio 3.3.0 has no bEXT/iXML support** — all typed chunk parsing is manual- All source files use implicit usings and nullable reference types (no `.editorconfig` needed)## Gotchas- `MergeCommand.Run` is `async Task<string>` but called via `Task.Run()` in the UI thread — don't change to fire-and-forget- `SplitCommand.AppendChunksToOutput` opens files with `FileMode.Append` — must run after `WaveFileWriter` is fully closed and flushed- `WavChunkParsers.ParseKnownChunks` currently passes all chunks through as "other" — the switch statement doesn't actually parse into typed metadata (that's done by `ExtractTypedMetadata`).
